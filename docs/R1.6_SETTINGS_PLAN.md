## P0 — Settings core and editors

- **Shared settings controls**: one mechanism for panel open/close, toggle, Escape/click-away, gear burst animation, keyboard focus and reset. Test with page settings, project settings and Visual Archive settings; respect reduced motion.
- **Live inspector**: lightweight translucent, movable inspector. Navigate to relevant page element on **setting selection only**, never on slider input; keep inspected content visible on narrow screens.
- **Scoped overrides & per-control reset**: explicit precedence `defaults → global → project → media-item → unsaved preview`; each slider has a reset-to-inherited action, an informative help tooltip (min/max/default/unit/impact) and a visible active override indicator.
- **Developer media manager**: upload images locally, edit captions, reorder, disable, restore, remove with confirmation and undo; distinguish **disabled** and **removed** in a versioned media manifest. Validate type, dimensions and total assets; use relative asset paths in exported packages, not persistent object URLs.
- **Content and section editor**: edit named text fields and links by stable IDs; add/reorder/hide/restore sections from approved templates; preview/undo before export. No arbitrary HTML insertion; sanitize/validate imported content to avoid script injection.
- **History and export**: undo/redo session operations and local snapshots. Export versioned JSON config plus media assets/manifest; import with schema validation, diff preview and rollback. Git commits remain the authoritative production history. No automatic publish from a public browser.

## P1 — Media, accessibility and button variants

- **Carousel SFX add-on**: lightweight ticks tied to card selection boundaries; velocity-sensitive intensity/pitch, debounced voices and mobile performance cap. Mute, volume, sound style, motion responsiveness, import sound file and local preview. Respect autoplay/user-gesture policies and reduced-motion preferences where useful.
- **ECG button variant**: `classic` remains default/fallback; `ecg` is an optional real button style, **not** a project gallery screenshot. Preserve click action and keyboard behavior. Later allow custom styles.
- **Public accessibility controls**: categories for text size, contrast, reduced motion and animation intensity, with immediate preview and independent reset. Never hide accessibility behind Developer Mode.
- **Export field guidance**: every numeric setting documents meaning, units, valid range, default and reset/inheritance behavior. Add a decoded view for `DM1-` export strings, validating input and padding when decoding Base64URL.
- **ECG Manual**: inspect original app and embedded iframe viewport/clipping and restore existing manual access without recreating its content.

## Security and persistence contract

- Developer Mode is a UX gate, **not security**. Visitors can inspect HTML/CSS/JS and may edit *their own* local browser state. Only repository permissions govern publication.
- Public visitors' preference keys must be separate from authoring drafts. Local storage is origin- and device-specific; it is not an editor database or a shared content source.
- Never embed a GitHub token or confidential secret in static site assets, browser localStorage, exported JSON or client JavaScript.
- Default to reversible hide/disable instead of destructive deletion. Keep a bounded local draft log; use descriptive Git commits and changelog for durable tracking.
- Prefer dedicated `site-config.json`, `content.json` and `media-manifest.json` files as a future refactor; integrate gradually to avoid breaking the existing standalone HTML site.

## Acceptance test matrix

- Desktop Chromium: 1440×900 and keyboard-only.
- Tablet width: 768×860.
- Phone width: 390×844; physically check Samsung Chrome and Samsung Internet.
- Verify no global horizontal overflow, Shadow DOM settings interoperability, click-away/Escape policy, resets, scope precedence, import/export round trip and undo/redo.
- Verify gallery disable/remove/reorder + captions with preview, all live demos and original ECG manual, classic/ECG button toggle and reduced motion behavior.
- Verify carousel audio after a gesture, mute, no runaway oscillation/voices, and smooth drag inertia.
- Document measured tests vs. unverified device behavior; never claim untested functionality.

## Release workflow

1. Keep `release/r1.5` as the immutable candidate pointer to the verified GitHub snapshot.
2. Review the `release/r1.5 → main` PR and finish owner QA before production deployment. The newer standalone R1.5 Review HTML file is *not* assumed identical to GitHub without a byte-by-byte comparison.
3. Develop R1.6 changes on `feature/r1.6-settings` and merge to `develop` only after regression testing.
4. Preserve `old-version` as the original website backup.
5. Use a PR for each release; after an approved merge, confirm the GitHub Pages deployment source and public smoke test.
